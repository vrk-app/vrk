# Запись разговора 01

## Контекст

Обсуждение предметной области для приложения по учету, обслуживанию и ремонту оборудования. Основной акцент сделан на средствах измерений, эталонах и логике их метрологического учета.

## Основные выводы

1. Основная сущность системы — не заявка, а оборудование.
2. Заявки, договоры, ремонты и обслуживание должны быть привязаны к конкретной единице оборудования.
3. Ключевая ценность приложения — наведение порядка в учете средств измерений и связанных с ними процессов.
4. Для части оборудования критично вести учет эталонов, с помощью которых выполняются поверка или калибровка.
5. По оборудованию должна сохраняться полная история: обслуживание, ремонт, поверки, связанные заявки и договоры.

## Что обсуждали по предметной области

### Средства измерений и эталоны

- Эталоны могут быть представлены как физические меры или другие средства, используемые для поверки и калибровки.
- Если устройство является средством измерения, то оно подпадает под требования 102-ФЗ «Об обеспечении единства измерений».
- Такие средства внесены в государственный информационный фонд средств измерений.
- У них есть регистрационные номера и данные о поверке.
- После очередной поверки сведения обновляются в федеральном информационном фонде.
- При этом фиксируются и данные об эталонах, с помощью которых проводилась поверка или калибровка.
- Поверку проходят не только средства измерений, но и сами эталоны.
- Для обоих типов объектов важны:
  - дата последней операции;
  - дата следующей операции;
  - дата следующей метрологической поверки.

### Категории оборудования

- Устройства диагностики тормозного оборудования вагона:
  - эталоны для них не используются.
- Средства диагностики для проверки буксового узла вагона:
  - используются для контроля узлов с подшипниками на оси;
  - для измерения диаметра колес эталоны уже есть.
- Дефектоскопы и средства неразрушающего контроля:
  - применяются для проверки осей, боковых рам, поперечных балок;
  - используются для выявления скрытых повреждений и трещин;
  - для них также есть эталоны.

## Значение для продукта

- Поток работы через заявки сам по себе недостаточен.
- Без детальной карточки оборудования заявочный процесс не несет ценности.
- Система должна в первую очередь учитывать оборудование как центральный объект.
- Уже вокруг оборудования строятся:
  - заявки на ремонт;
  - договоры;
  - история обслуживания;
  - история ремонтов;
  - история метрологических операций.

## Предварительная модель данных

### Справочник оборудования

Должна существовать база оборудования, где для каждой единицы или модели хранятся:

- тип оборудования;
- модель;
- производитель;
- принадлежность к средствам измерений;
- регистрационные и учетные данные;
- информация о поверке;
- информация об эталонах, если они применяются.

### История событий

Отдельно должна храниться история операций по оборудованию, где фиксируются:

- `equipment_id`;
- `request_id`;
- дата заявки;
- тип события;
- сведения о ремонте или обслуживании;
- связь с договором при необходимости.

Это позволит отслеживать все, что происходило с конкретным оборудованием, через связанные сущности.

## Следующие шаги

1. Повторно созвониться и посмотреть структуру связей на экране.
2. Доработать перечень вопросов по оставшейся части предметной области.
3. Уточнить состав карточки оборудования:
   - какие поля обязательны;
   - как учитывать поверку;
   - как учитывать эталоны;
   - как различать типы диагностического оборудования.
