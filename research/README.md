# Research Usage

Этот каталог хранит результаты исследовательского ETL по контрагентам и контрактам.

## Где смотреть результат

Для текущего исследования ВРК-1 основной каталог:

- `research/vrk1_checko_2010_2019_20260316/`

Внутри него:

- `contracts.csv` - все найденные релевантные контракты заказчика.
- `summary.csv` - агрегаты по подрядчикам и обогащенные данные по компаниям.
- `sources.json` - служебное описание источников и ссылок.
- `contractors/*.csv` - детализация контрактов по каждому подрядчику.

Обычно работа начинается с двух файлов:

1. `summary.csv` - чтобы понять список подрядчиков, суммы и пропуски.
2. `contracts.csv` - чтобы проверить конкретные договоры, даты и ссылки на источник.

Если нужно разбирать отдельного подрядчика, открой путь из поля `contracts_file` в `summary.csv`.

## Как запускать ETL

Базовый запуск:

```bash
python3 scripts/market_research.py run \
  --customer-ogrn 1117746294104 \
  --years 2010 2011 2012 2013 2014 2015 2016 2017 2018 2019 \
  --out research/vrk1_checko_2010_2019_20260316 \
  --disable-api
```

Если доступен ключ Checko API и нужен API-режим, убери `--disable-api`.

## Как скрипт пишет результат

Для запуска по одному customer скрипт пишет файлы сразу в каталог, переданный в `--out`, без дополнительной вложенной папки по OGRN.

Поведение при повторном запуске:

- без `--resume` существующий экспорт не перетирается;
- если `--out` уже содержит результат, скрипт автоматически создаст соседний каталог с суффиксом `_2`, `_3` и так далее;
- с `--resume` скрипт работает в указанном каталоге и может обновлять уже существующий экспорт.

Пример:

- первый запуск: `research/vrk1_checko_2010_2019_20260316`
- второй запуск без `--resume`: `research/vrk1_checko_2010_2019_20260316_2`

## Как пользоваться результатом

### Проверка подрядчиков

Смотри:

- название подрядчика в `summary.csv`
- `contractor_inn`
- `total_contract_value`
- `employee_count`
- `revenue_value`
- `source_card_url`

Это позволяет быстро отделить крупных подрядчиков от хвоста и понять, где еще есть пробелы.

### Проверка конкретного контракта

Смотри:

- `contract_number`
- `contract_date`
- `contract_subject`
- `contract_value`
- `source_url`

в `contracts.csv` или в соответствующем `contractors/*.csv`.

### Проверка полноты выгрузки

Полезный порядок:

1. Найти пустые поля в `summary.csv`.
2. Перейти в `contractors/*.csv` по `contracts_file`.
3. Сверить ссылки в `source_url` и `source_card_url`.
4. При необходимости запустить новую итерацию ETL в новый `--out`, чтобы не затереть текущий снимок.

## Практическое правило

Текущий каталог в `research/` стоит считать снимком результатов на конкретную дату. Новые итерации лучше писать в новый каталог, а не поверх старого, если задача не требует осознанного `--resume`.
