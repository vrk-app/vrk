# ADR-0004: Offline Sync Approach For Field Engineer

Статус: accepted  
Дата: 2026-04-11

## Контекст

PRD и roadmap требуют offline-first поведение для инженерного контура, но текущий репозиторий еще не содержит `apps/field`. Нужно заранее зафиксировать минимально безопасный подход, чтобы последующие этапы не расходились в ожиданиях.

## Решение

Для MVP принять следующий offline-sync подход:

- field-клиент строится как `PWA-first` приложение;
- инженер может создавать и редактировать локальные черновики checklist/work log данных без сети;
- первичная синхронизация выполняется вручную после восстановления связи;
- сервер остается source of truth для подтвержденного состояния заявки;
- клиент отправляет идемпотентные операции или пачки изменений с client-generated identifiers;
- конфликтные или просроченные изменения сервер отклоняет явно, а клиент переводит их в состояние retry/manual review.

## Что входит в MVP

- локальное хранение незавершенных действий;
- отображение pending sync state;
- ручной retry после reconnect;
- безопасная доставка полевых данных в основной request flow.

## Что не входит в MVP

- сложный multi-device merge;
- background sync как единственный обязательный путь;
- офлайн-редактирование всего подряд contractor/customer кабинета;
- автоматическое разрешение конфликтов на уровне rich domain merge.

## Последствия

- Stage 06 должен сначала доказать offline draft + manual sync, а не полный distributed sync engine.
- API следующих этапов должны проектироваться с учетом идемпотентности и повторной отправки.
- Документы, приемка и финальные статусные переходы остаются server-validated even if draft capture happened offline.
